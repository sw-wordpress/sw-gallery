# Release

How a version is cut, built, verified and published. Decisions: D8 (self-update module) and D9 (1.0 via GitHub releases only) in `decisions.md`.

## Version: one source
The `Version:` header of `sw-gallery.php` is the source. `SWGALLERY_VERSION` (used for every `ver=` cache-busting parameter), the four `package.json` + lockfiles (`apps/admin`, `assets`, `assets/blocks`, `e2e`) and the newest `CHANGELOG.md` section must equal it.

```bash
bin/version.sh get                 # print
bin/version.sh check               # fails on drift; part of `composer check`, PHPUnit (VersionScriptTest) and the release workflow
bin/version.sh set 1.0.0           # writes everywhere, turns "## [Unreleased]" into "## [1.0.0] - <today>", then checks
```
The version utility also accepts pre-release suffixes (`1.0.0-rc.1`); verified update releases and `make release` accept stable `X.Y.Z` only. The compare links at the end of `CHANGELOG.md` are maintained by hand. `composer.json` has no `version` (Composer derives it; the ZIP does not ship it).

## Procedure
1. Configure the protected signing environment and trusted public keys using [the operations guide](GITHUB-UPDATES-BETRIEB.md).
2. Maintain `[Unreleased]` notes and pass the PR checks; tests run exclusively on pull requests.
3. Optional local package: `make dist` (no publication).
4. Explicit publication: `make release VERSION=1.2.3` from a clean checkout. This bumps all version metadata, commits, creates an annotated stable tag and atomically pushes branch plus tag. The tag triggers the protected signing workflow. No production key is generated by this command.

## What `release.yml` does
The `plugin-releases` environment authorizes key access. Validate stable `[v]X.Y.Z` tag/headers; embed the signing public key while preserving old keys and rejecting conflicting IDs; build/verify ZIP; upload to a new draft; sign actual asset IDs; upload manifest and signature; download and verify the complete artifact set with the runtime verifiers; publish. Existing releases are never overwritten. Missing signing configuration aborts before upload. No test suites run in this workflow. The updater accepts stable three-component versions only; local prerelease builds are never offered through this provider.

## The ZIP
`bin/build-zip.sh [dir]` -> `dist/sw-gallery-<version>.zip`, top-level folder `sw-gallery/`. Needs bash, zip, node/npm, php, composer, msgfmt (gettext); no Docker. It runs `npm ci` + build for `apps/admin`, `assets`, `assets/blocks` (`SWG_ZIP_REUSE_NODE_MODULES=1` skips `npm ci`, local only), checks translations (`bin/i18n.sh check`), copies the allowlist below into a staging directory, compiles the `.mo` files from the `.po` files there, runs `composer install --no-dev --classmap-authoritative` **in the staging copy** (never the working `vendor/`) and zips a sorted file list with normalised modes and mtimes (`SOURCE_DATE_EPOCH`, default: last commit time). Same commit -> byte-identical ZIP. It fails when it changed the working tree.

Shipped: `sw-gallery.php`, `uninstall.php`, `CHANGELOG.md`, `LICENSE`, `THIRD-PARTY-NOTICES.md` (all three required; the GitHub `README.md` is not shipped; a wordpress.org `readme.txt` would be), `packages/**/*.php`, `vendor/` (generated autoloader only), `languages/*.{pot,po,mo,json}`, `assets/build/`, `assets/admin/` (incl. fonts and `.vite/manifest.json`), `assets/blocks/block.json` + `assets/blocks/build/`, `assets/media-library/media-library.js`, `assets/js/sw-gallery-updates.js` and the verified updater/config classes under `packages/wordpress/src/Update/`.
Not shipped: tests, `e2e`, `apps`, `bin`, `docs` (docs live in the repository), `node_modules`, source maps, lockfiles, `composer.json`, dev tooling, dotfiles. There are **no runtime Composer dependencies**, so Mozart prefixing is not needed; the script stops with an error when one is added so the prefixing step (`SWGallery\Dependencies\`) is not forgotten.
The block JSON catalog is named after the md5 of the **path** `assets/blocks/build/index.js` (WordPress rule), not of its content: the build order of blocks and `bin/i18n.sh` does not matter; the verifier checks the name.

## Verification
`bin/verify-zip.sh <zip>` (static, also run by the workflow): intact ZIP named `sw-gallery-<semver>.zip` with everything below `sw-gallery/`; top-level and `assets/` allowlists; forbidden paths (tests, dev dependencies, `.env*`, `.npmrc`, lockfiles, `composer.json`, `*.dist`, source maps unless `SWG_ZIP_ALLOW_SOURCEMAPS=1`, TypeScript/Vue sources, coverage, docs, bin, e2e, apps, VCS/CI/editor files); content heuristics (private keys, GitHub/AWS/Slack/npm tokens, absolute developer paths such as `/var/www`, `/home/<user>`); header version = file name = `SWGALLERY_VERSION`, real Plugin URI, matching `CHANGELOG.md` section; `php -l` on every PHP file and a loading autoloader; required files (`LICENSE`, `THIRD-PARTY-NOTICES.md`, block, manifests with every referenced file, `.mo` per `.po`, block JSON catalog); size budget 3 MiB (`SWG_ZIP_MAX_BYTES`; the 0.1.0 ZIP is ~0.9 MiB). `TODO` markers are not checked (minified code). `VerifyZipScriptTest` builds tiny fake ZIPs and proves acceptance and rejection.

Install test: `bin/test-zip-install.sh <zip> [--keep]` verifies the ZIP, starts a throw-away WordPress + MariaDB (`tests/e2e-env/compose.zip.yml`, random port, own compose project, removed afterwards), installs the ZIP with `wp plugin install` + `activate` (source tree **not** mounted) and runs `e2e/zip/zip-smoke.spec.ts` via `e2e/playwright.zip.config.ts`: plugin active in the right version and admin app mounts with `ver=`, gallery created and rendered by the shortcode with a working lightbox, block editor registers the block from the ZIP, no failing plugin request or console error; afterwards `debug.log` must contain no PHP notice/warning/deprecation/fatal from `plugins/sw-gallery/`. `SWG_E2E_WP_IMAGE`/`SWG_E2E_CLI_IMAGE` select another WordPress/PHP. The normal `bin/test-e2e.sh` is unchanged.

## Dependency audit
`.github/workflows/security-audit.yml` (daily, manual, PRs touching a lockfile) runs `bin/security-audit.sh`: shipped dependencies (`composer audit --locked --no-dev`, `npm audit --omit=dev --audit-level=high` for `apps/admin`, `assets`, `assets/blocks`) fail the run; development tooling and the dev-only `e2e` project are recorded (job summary, artifact `audit-report`) but do not block.

## Operator decisions
Production key, protected GitHub environment/tag rules and the first signed release remain operator tasks. The delivered keyring is empty; this change does not establish production update trust. The GitHub Update URI/provider must be removed from a future WordPress.org build; see [rotation and Store migration](GITHUB-UPDATES-BETRIEB.md).
